**claude-afk — плагин для Claude Code, который переносит твой живой разговор с
Claude Code в Telegram, когда ты отходишь от компьютера.** Пишешь `/afk` — и
общаешься дальше с телефона: **пишешь что угодно обычными словами, и Claude
отвечает**, ровно как за столом. Это переписка, а не пульт с кнопками.

Твоё сообщение попадает в ту сессию, в которой ты уже был, — с полной историей,
инструкциями проекта, скиллами и инструментами. Тем же каналом идут две
добавки: «да»/«нет» отвечает на запрос разрешения, когда он возникает, а одно
живое сообщение показывает, какой инструмент работает прямо сейчас.

Написан на чистой стандартной библиотеке Python. Ни демона, ни tmux, ни Node.js,
ни пакетов для установки, ни правок в `settings.json`.

---

## Что делает claude-afk

- **Ведёт весь разговор в обе стороны.** Всё, что ты напишешь в Telegram —
  вопрос, новая задача, поправка, «нет, сделай иначе» — становится твоей
  следующей репликой, а полный ответ Claude приходит в чат.
- **Оставляет тебя в той же сессии**, а не в новой: тот же контекст, те же
  инструкции проекта, та же модель.
- **Подтверждает или отклоняет вызовы инструментов с телефона**, чтобы сессия не
  вставала на первом же запросе разрешения, пока тебя нет за клавиатурой. Это
  удобство поверх разговора, а не его смысл.
- **Показывает прогресс вживую** одним сообщением, которое правится на месте:
  число шагов, время и текущий инструмент.
- **Выключается сам** — по лимиту ходов, по потолку времени или когда никто не
  отвечает. Он не работает без присмотра бесконечно.

## Как пользоваться Claude Code с телефона

Пишешь `/afk` в Claude Code и уходишь. С этого момента разговор идёт в Telegram:

```
ты:   почини падающие тесты
      ⏳ Принял, работаю…                        ← приходит сразу
      ⏳ Работаю… · 1 шаг · 2с
      └ Bash: pytest tests/ -q                   ← то же сообщение, правится на месте
      ⏳ Работаю… · 7 шагов · 1м 12с
      └ Read: src/conftest.py
                                                 ← удаляется
      🤖 demo · ход 3/40
      Починил — фикстура текла временной папкой…  ← новым сообщением, с уведомлением

      🔐 Запрошено разрешение
      Инструмент: Bash
      git push origin main
      Ответь: да / нет
ты:   да
```

Пока идёт работа, правится **одно** сообщение — чат не засоряется. Ответ приходит
новым сообщением намеренно: правка старого не даёт уведомления, а законченный ход
— это ровно то, о чём нужно узнать.

| Что отправляешь в Telegram | Что происходит |
|---|---|
| **любой обычный текст** — вопрос, задача, поправка | **становится твоей следующей репликой, Claude отвечает в чат.** Это основной режим |
| `да` / `нет` | ответ на запрос разрешения, когда он висит |
| `/status` | проект, номер хода, остаток времени |
| `/back` | выключить AFK |

За компьютером выключается через `/afk off`.

## Установка

```bash
/plugin marketplace add Pupok462/claude-afk
```

```bash
/plugin install claude-afk@claude-afk-marketplace
```

Плагин приносит свои хуки — установка регистрирует всё сама. Проверенный
инвентарь после установки: **1 скилл, 4 хука, ~164 токена** постоянного контекста.

### Подключить бота (один раз, ~2 минуты)

1. В Telegram: [@BotFather](https://t.me/BotFather) → `/newbot` → имя и username
   на `bot`.
2. Открой своего бота, нажми **Start**, напиши ему что угодно. Бот не может
   написать первым — это запрет Telegram.
3. В **своём** терминале, не через Claude, чтобы токен не попал в переписку с ИИ:

   ```bash
   python3 ~/.claude/plugins/*/claude-afk/*/skills/afk/scripts/afk_setup.py
   ```

Ввод токена скрыт. Скрипт проверит токен, найдёт chat_id, отправит тестовое
сообщение и запишет `~/.claude/afk/config.json` с правами `0600`.

## Как это работает

Хук `Stop` в Claude Code может не дать ходу завершиться. Когда он возвращает

```json
{"decision": "block", "reason": "<твоё сообщение из Telegram>"}
```

рантайм подставляет этот текст как следующую реплику пользователя. Весь мост —
этот один контракт.

```
        ход закончен
Claude ──────────────► хук Stop ──► sendMessage ──► Telegram
                          │                             │
                          │      long-poll getUpdates   │
                          ◄─────────────────────────────┘
                          │
              {"decision":"block","reason":"<твой текст>"}
                          │
                          ▼
              рантайм подставляет это как новую реплику
```

Четыре хука, все выключаются одним файлом состояния (`~/.claude/afk/active.json`):

| Хук | Что делает | Таймаут |
|---|---|---|
| `Stop` | гасит тикер, отправляет законченный ход, ждёт ответ, возвращает его в сессию | 3600 с |
| `PostToolUse` | правит живой тикер после каждого вызова инструмента | 20 с |
| `PermissionRequest` | спрашивает «да/нет» на вызов инструмента | 1200 с |
| `Notification` | сообщает, что сессия чего-то ждёт | 30 с |

Подробности: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Это новая сессия или продолжение текущей?

Продолжение текущей. Ни второго агента, ни перезапуска `claude -p` в headless, ни
отдельного системного промпта. Твоё сообщение из Telegram попадает в ту сессию, в
которой ты уже был, — с полной историей, твоим `CLAUDE.md`, скиллами и
инструментами.

Единственная добавка — короткая обёртка, которая сообщает Клоду, что ответ пришёл
с телефона, и просит писать компактно. Она лежит в
[`hook_stop.py`](skills/afk/scripts/hook_stop.py), сама строка — в
[`i18n/ru.json`](skills/afk/i18n/ru.json), так что её видно и можно поменять.

Это важно при сравнении инструментов: мост, который на каждое сообщение дёргает
`claude -p`, каждый раз стартует с пустого контекста.

## Можно ли подтверждать разрешения Claude Code из Telegram?

Да. Когда вызову инструмента нужно решение, хук `PermissionRequest` отправляет в
чат имя инструмента и его аргументы и ждёт «да» или «нет».

Без этого удалённая работа разваливается на первом же запросе: сессия просто
встаёт на экране, пока кто-нибудь не вернётся. Разрешения **ретранслируются, а не
выдаются автоматически** — каждое остаётся явным человеческим ответом, а если
никто не ответил вовремя, запрос уходит на экранный диалог, а не решается за тебя.

## Безопасно ли подтверждать вызовы инструментов с телефона?

Пойми размен до того, как включишь: **у кого доступ к твоему Telegram — у того
доступ к этой сессии Claude Code.** Нужны блокировка устройства и двухэтапная
аутентификация в Telegram.

Что мост делает, чтобы ограничить ущерб:

| Механизм | Поведение |
|---|---|
| Белый список чата | читается только настроенный `chat_id`, остальное логируется и отбрасывается |
| Защита от устаревших сообщений | очередь обновлений очищается на старте, всё старше времени старта отбрасывается — очередь нельзя переиграть как инструкции |
| Лимит ходов | `--max-turns`, по умолчанию 40 |
| Потолок по времени | `--hours`, по умолчанию 8 |
| Таймаут ответа | `--wait-minutes`, по умолчанию 45 |
| Хуки падают наружу | любое исключение логируется, хук выходит с `0` — сломанный мост не подвесит сессию |
| Никакого автоодобрения | таймаут разрешения уводит вопрос на экран, а не разрешает и не запрещает |

Твои существующие хуки `PreToolUse` продолжают работать: подтверждение из Telegram
не обходит то, что уже стережёт коммиты, пуши и разрушительные команды.
Подробнее: [docs/SECURITY.md](docs/SECURITY.md).

## Ограничения

Названы прямо, потому что именно они решают, подходит ли это тебе:

- **Гранулярность ответа — ход.** Тикер идёт в реальном времени, ответ приходит по
  завершении хода. Рассуждения не транслируются.
- **Сессия должна быть жива.** Мост живёт внутри запущенной сессии Claude Code:
  закроешь её — закончится и он.
- **Ответ после таймаута не подхватится.** За пределами `--wait-minutes` ход
  завершается и AFK выключается; сообщение останется в чате, но в сессию не попадёт.
- **Не для фоновых и запланированных прогонов** — там некому вести диалог.

## Почему важен ноль зависимостей

Эти скрипты запускаются как хуки Claude Code, на том Python, который случился на
машине, в окружении, которое ты не контролируешь. Каждая зависимость — ещё один
способ для хука сломаться ровно в тот момент, когда ты не за столом. Отсюда:
только стандартная библиотека, Python 3.9+ и хуки, которые при любой ошибке
выходят с `0`, а не подвешивают сессию.

Цена при выключенном AFK — запуск процесса, который читает один отсутствующий
файл и выходит.

## claude-afk против других мостов Claude Code ↔ Telegram

Проектов, сажающих Claude Code в Telegram, несколько. Почти все **владеют
процессом агента**: сами его запускают или управляют панелью `tmux` через
инъекцию клавиш. claude-afk вместо этого **цепляется к интерактивной сессии,
перед которой ты уже сидишь**.

| Проект | Подход | Требует | Подтверждение разрешений | Будит остановленную сессию |
|---|---|---|---|---|
| **claude-afk** | хуки Claude Code | только Python 3.9+ | да, текстом «да»/«нет» | нет |
| [jsayubi/ccgram](https://github.com/jsayubi/ccgram) | хуки + tmux/Ghostty/PTY | Node 18+ | да, инлайн-кнопки, включая *Always* | да |
| [alexei-led/ccgram](https://github.com/alexei-led/ccgram) | мост через tmux/herdr | Python 3.14+, tmux | не описано | да |
| [oscarsterling/claude-telegram-remote](https://github.com/oscarsterling/claude-telegram-remote) | демон + tmux + MCP | tmux, 2 бота, MCP-плагин | нет | да |
| [Open-ACP/OpenACP](https://github.com/Open-ACP/OpenACP) | протокол ACP | ACP-агент | не описано | да |
| [RichardAtCT/claude-code-telegram](https://github.com/RichardAtCT/claude-code-telegram) | полноценный бот доступа | Python, хост для бота | — | да |

**Бери claude-afk**, если работаешь в десктопном приложении Claude Code (где нет
панели tmux, куда печатать), не хочешь ставить ничего кроме Python и хочешь
передать ту сессию, в которой уже находишься. **Бери любой другой**, если живёшь
в tmux и хочешь кнопки, управление клавишами или пробуждение уже остановленной
сессии.

## Частые вопросы

**Можно ли свободно переписываться в Telegram или только жать «да»/«нет»?**
Свободно. Обычный текст — основной режим: пишешь вопрос, новую задачу, поправку
— всё, что напечатал бы с клавиатуры, — и это становится твоей следующей
репликой, а полный ответ Claude приходит в чат. «Да» и «нет» особенные только
когда висит запрос разрешения; в остальное время это просто слова. Мост,
умеющий одни апрувы, был бы пультом, а не перепиской.

**Работает ли в десктопном приложении Claude Code?**
Да, ради этого случая он и сделан. Инструменты на инъекции клавиш в tmux — нет.

**Работает ли на Linux и macOS?**
Да. CI гоняет тесты на Ubuntu с Python 3.9, 3.11 и 3.13 плюс на macOS. Windows не
проверялся.

**Можно ли вести несколько проектов одновременно?**
Нет, намеренно. Состояние привязывается к первой сессии, чей хук сработал, — второе
окно Claude Code не перехватывается.

**Сколько это стоит?**
Нисколько. Лицензия MIT, обращение идёт напрямую к бесплатному Telegram Bot API.
Использование самого Claude Code тарифицируется как обычно.

**На каком языке интерфейс?**
По умолчанию английский, русский в комплекте. Выбор — по `AFK_LANG` или ключу
`lang` в конфиге. Новый язык — это один JSON-файл в
[`skills/afk/i18n/`](skills/afk/i18n/); отсутствующие ключи падают на английский
поштучно, так что неполный перевод рабочий.

**Где хранится токен бота?**
`~/.claude/afk/config.json`, права `0600`, пишется скриптом, который читает токен
через `getpass`. Он не появляется ни на экране, ни в истории shell, ни в `ps`, ни
в переписке с ИИ. `.gitignore` и проверка в CI не дают его закоммитить.

**Как удалить?**
Снять плагин и `rm -rf ~/.claude/afk`. Токен отозвать в @BotFather, если бот больше
не нужен.

## Тесты

38 сквозных проверок против локальной заглушки Telegram Bot API — без сети, без
аккаунта Telegram, без зависимостей:

```bash
python3 tests/test_bridge.py
```

Тесты запускают настоящие хуки подпроцессами — ровно так, как это делает Claude
Code — и покрывают доставку, инжект ответа, привязку к сессии, `/back`, таймауты,
отказ чужому чату, устаревшую очередь, разбиение длинных сообщений, разрешения
да/нет, лимит ходов, битое состояние, жизненный цикл тикера и откат локали.
