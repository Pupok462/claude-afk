# claude-afk

**Отойти от компьютера, не обрывая разговор.** Пишешь `/afk` — и живая сессия
Claude Code продолжается в Telegram: законченные ходы приходят на телефон, твой
ответ возвращается в сессию следующей репликой, разрешения на инструменты
подтверждаются словом «да», а живой тикер показывает, что происходит прямо
сейчас.

Ни демона, ни tmux, ни Node, ни зависимостей — только стандартная библиотека Python.

[English version](README.md)

## Как это выглядит

```
ты:   почини падающие тесты
      ⏳ Принял, работаю…                        ← приходит сразу
      ⏳ Работаю… · 1 шаг · 2с
      └ Bash: pytest tests/ -q                   ← то же сообщение, правится на месте
      ⏳ Работаю… · 7 шагов · 1м 12с
      └ Read: src/conftest.py
                                                 ← удаляется
      🤖 demo · ход 3/40
      Починил — фикстура текла временной папкой…  ← новым сообщением, с уведомлением

      🔐 Запрошено разрешение
      Инструмент: Bash
      git push origin main
      Ответь: да / нет
ты:   да
```

Пока идёт работа, правится **одно** сообщение — чат не засоряется. Ответ
приходит новым сообщением намеренно: правка старого не даёт уведомления, а
законченный ход — это ровно то, о чём нужно узнать.

## Зачем, если такое уже есть

Мостов «Claude Code в Telegram» много. Почти все владеют процессом агента: сами
его запускают или управляют панелью `tmux` через инъекцию клавиш. Для терминала
на VPS это отличный подход.

`claude-afk` устроен иначе — он цепляется к **той интерактивной сессии, перед
которой ты уже сидишь**. Разговор передаётся с середины задачи и так же
забирается обратно за клавиатурой, с полным контекстом с обеих сторон. Работает
в десктопном приложении Claude Code, где панели tmux просто нет, и не добавляет
в систему ничего, кроме четырёх Python-файлов, которые при выключенном AFK
завершаются за миллисекунды.

Честное сравнение с аналогами — [в конце](#аналоги).

## Установка

```bash
/plugin marketplace add Pupok462/claude-afk
```

```bash
/plugin install claude-afk@claude-afk-marketplace
```

Плагин приносит свои хуки — в `settings.json` вставлять ничего не надо.

### Подключить бота (один раз, ~2 минуты)

1. В Telegram: [@BotFather](https://t.me/BotFather) → `/newbot` → имя и username
   на `bot`.
2. Открой своего бота, нажми **Start** и напиши ему что угодно. Бот не может
   написать первым — это запрет Telegram.
3. В **своём** терминале (не через Claude — токен не должен попасть в переписку
   с ИИ):

   ```bash
   python3 ~/.claude/plugins/*/claude-afk/*/skills/afk/scripts/afk_setup.py
   ```

   Ввод токена скрыт. Скрипт проверит токен, найдёт chat_id, отправит тестовое
   сообщение и запишет `~/.claude/afk/config.json` с правами `0600`.

Если работаешь из клона — путь `skills/afk/scripts/afk_setup.py`.

## Использование

В Claude Code пишешь `/afk` — или просто «мне надо отойти». И уходишь.

| В Telegram | Что делает |
|---|---|
| обычный текст | становится следующей репликой в сессии |
| `да` / `нет` | ответ на запрос разрешения |
| `/status` | проект, номер хода, остаток времени |
| `/back` | выключить AFK |

За компьютером: `/afk off`.

Параметры при включении: `--hours 8` (потолок сессии), `--max-turns 40` (лимит
обменов), `--wait-minutes 45` (сколько один ход ждёт ответа).

## Как устроено

```
        ход закончен
Claude ──────────────► хук Stop ──► sendMessage ──► Telegram
                          │                             │
                          │      long-poll getUpdates   │
                          ◄─────────────────────────────┘
                          │
              {"decision":"block","reason":"<твой текст>"}
                          │
                          ▼
              рантайм подставляет это как новую реплику
```

Четыре хука, все выключаются одним файлом состояния (`~/.claude/afk/active.json`):

| Хук | Что делает | Таймаут |
|---|---|---|
| `Stop` | гасит тикер, отправляет законченный ход, ждёт ответ, возвращает его в сессию | 3600 с |
| `PostToolUse` | правит живой тикер после каждого вызова инструмента | 20 с |
| `PermissionRequest` | спрашивает «да/нет» на вызов инструмента | 1200 с |
| `Notification` | сообщает, что сессия чего-то ждёт (`idle_prompt`, `agent_needs_input`) | 30 с |

Состояние привязывается к первой сессии, чей хук сработал, — второе окно Claude
Code не перехватывается. Подробности: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Ограничения — честно

- **Гранулярность ответа — ход.** Тикер идёт в реальном времени, сам ответ
  приходит по завершении хода. Рассуждения не транслируются.
- **Сессия должна быть жива.** Мост живёт внутри запущенной сессии Claude Code:
  закроешь её — закончится и он.
- **Ответ после таймаута не подхватится.** Не ответил дольше `--wait-minutes`
  (по умолчанию 45) — ход завершается, AFK выключается. Сообщение останется в
  чате, но в сессию не попадёт.
- **Не для фоновых и запланированных прогонов** — там некому вести диалог.

## Безопасность

- Принимается только настроенный `chat_id`; всё остальное логируется и
  отбрасывается.
- Сообщения, отправленные **до** включения AFK, не подхватываются: очередь
  обновлений очищается на старте, всё старше времени старта отбрасывается.
- Бюджеты: число ходов, ожидание одного ответа и жёсткий потолок по времени.
- Любая ошибка внутри хука логируется, хук выходит с `0` — сломанный мост не
  может подвесить сессию.
- Разрешения ретранслируются, а не выдаются автоматически. Каждое — явное
  человеческое «да».

**Пойми размен:** подтверждая вызовы инструментов с телефона, ты делаешь доступ
к Telegram доступом к сессии Claude Code. Блокировка устройства и двухэтапная
аутентификация в Telegram обязательны. Подробнее: [docs/SECURITY.md](docs/SECURITY.md).

## Настройка

`~/.claude/afk/config.json` (права `0600`, создаётся при setup):

| Ключ | Смысл |
|---|---|
| `bot_token` | из @BotFather |
| `chat_id` | единственный чат, которому разрешено управлять сессией |
| `lang` | язык интерфейса — `en`, `ru` или любой файл из `skills/afk/i18n/` |

Переменные окружения: `AFK_LANG`, `AFK_HOME` (каталог состояния),
`AFK_TG_API_BASE` (для тестовой заглушки).

Новый язык — это JSON-файл в `skills/afk/i18n/`; отсутствующие ключи падают на
английский поштучно, так что неполный перевод рабочий.

## Тесты

38 сквозных проверок против локальной заглушки Telegram API. Без сети, без
аккаунта Telegram, без зависимостей:

```bash
python3 tests/test_bridge.py
```

Тесты запускают настоящие хуки подпроцессами — ровно так, как это делает Claude
Code — и покрывают доставку, инжект ответа, привязку к сессии, `/back`,
таймауты, отказ чужому чату, устаревшую очередь, разбиение длинных сообщений,
разрешения да/нет, лимит ходов, битое состояние, жизненный цикл тикера и откат
локали.

## Аналоги

Стоит знать до выбора:

- [jsayubi/ccgram](https://github.com/jsayubi/ccgram) — ближайший родственник.
  Тоже на хуках, плюс инлайн-кнопки (Allow/Deny/**Always**/Defer), инъекция
  клавиш в tmux/Ghostty/PTY и фоновый сервис под супервизором. Требует Node 18+.
- [alexei-led/ccgram](https://github.com/alexei-led/ccgram) — мост через
  tmux/herdr сразу для Claude Code, Codex и Gemini, параллельные сессии
  топиками, голосовой ввод. Требует Python 3.14+ и tmux.
- [oscarsterling/claude-telegram-remote](https://github.com/oscarsterling/claude-telegram-remote) —
  23 команды, откат по чекпоинтам; нужны tmux, два бота и MCP-плагин.
- [Open-ACP/OpenACP](https://github.com/Open-ACP/OpenACP) — мост по протоколу
  ACP сразу в Telegram, Discord и Slack.
- [RichardAtCT/claude-code-telegram](https://github.com/RichardAtCT/claude-code-telegram) —
  давно живущий полноценный бот удалённого доступа.

Бери `claude-afk`, если нужен десктопный клиент, ноль зависимостей и передача
той сессии, в которой уже работаешь. Бери любой другой, если живёшь в tmux и
хочешь кнопки и управление клавишами.
